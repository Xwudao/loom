# Loom

[English](README.md) | 简体中文

**Loom 是 Go 的编译期依赖注入工具。**

使用 `loom.Graph`、普通构造函数和一小套标记 API 声明依赖图。`loom generate`
读取声明，并生成按正确顺序调用构造函数的普通 Go 代码。生成的代码没有反射、服务定位器或运行时容器——只有一个函数。

```go
var AppGraph = loom.Graph[*Application](
    loom.WithContext(),
    loom.Provide(NewConfig),
    loom.Provide(NewLogger),
    loom.Provide(NewDatabase),
    loom.Provide(NewRepository[User]),
    loom.Provide(NewRepository[Article]),
    loom.As[UserStore](NewUserStore),
    loom.Provide(NewUserService),
    loom.Provide(NewHTTPServer),
    loom.Provide(NewApplication),
)
```

```bash
loom generate ./...
```

```go
// Code generated by loom. DO NOT EDIT.

func InitApp(ctx context.Context) (*Application, *loom.Lifecycle, error) {
    lifecycle := loom.NewLifecycle()

    config := NewConfig()
    logger := NewLogger(config)

    database, databaseCleanup, err := NewDatabase(config)
    if err != nil {
        return nil, nil, errors.Join(err, lifecycle.Rollback(ctx))
    }
    lifecycle.AddCleanup(databaseCleanup)

    userRepository := NewRepository[User](database)
    articleRepository := NewRepository[Article](database)
    userStore := NewUserStore(userRepository, logger)
    userService := NewUserService(userStore, logger)
    httpServer := NewHTTPServer(lifecycle, config, logger, userService)
    application := NewApplication(config, logger, database, httpServer, userService)

    return application, lifecycle, nil
}
```

两个 `Repository[...]` 实例共用**一个** `*Database`；接口显式绑定；资源按逆序释放。

## 为什么选择 Loom

| | |
| --- | --- |
| **编译期** | 依赖图由 `go/types` 解析，而非在运行时解析。 |
| **泛型优先** | `Repository[User]` 与 `Repository[Article]` 是不同的依赖键，通过 `types.Identical` 判定。 |
| **无反射** | 运行时代码不含 `reflect`、`map[reflect.Type]` 或容器。 |
| **易读输出** | 生成的代码如同手写，变量名具有明确含义。 |
| **出色的诊断** | 缺失 provider、循环和重复项都会给出完整依赖路径及源码位置。 |
| **对 gopls 友好** | 图声明是普通包级变量，不隐藏在构建标签后。 |
| **生命周期支持** | 有序的启动/停止钩子和构造函数清理；失败时自动回滚。 |
| **确定性** | 相同输入始终产生逐字节相同的输出。 |
| **无需 stub 文件** | 图位于普通文件中，重构和查找引用均可正常工作。 |

## 安装

将生成器固定到模块中，使所有开发者和 CI 使用同一版本：

```bash
go get -tool github.com/Xwudao/loom/cmd/loom@latest
go tool loom generate ./...
```

或一次性安装二进制文件：

```bash
go install github.com/Xwudao/loom/cmd/loom@latest
```

`loom` 面向 Go 1.25 及更高版本设计（使用 Go 1.27 构建和测试）。

## 从 Wire 迁移

| Wire | Loom |
| --- | --- |
| `wire.NewSet(a, b)` | `loom.Module(loom.Provide(a), loom.Provide(b))` |
| `wireinject` stub 中的 `wire.Build(...)` | 普通文件中的 `loom.Graph[T](...)` |
| `wire.Bind(new(I), new(*C))` | `loom.As[I](NewC)` |
| injector `(T, func(), error)` | `(T, *loom.Lifecycle, error)` |
| `defer cleanup()` | `defer lifecycle.Stop(ctx)` |

有两项区别值得特别注意。

**`As` 替代 `Provide`，不是与其并列。** `loom.As[I](NewC)` 会注册 `NewC`，并将同一实例暴露为 `I`；因此同时列出二者会成为重复 provider。Loom 会直接说明：

```
loom: multiple providers found for *store
providers:
    internal/app/providers.go:33:15  NewStore()
    internal/app/providers.go:34:17  NewStore()

hint:
    loom.As[Store](NewStore) already provides both *store and Store; remove the separate loom.Provide(NewStore)
```

**没有 stub 文件。** Wire 将 injector 放在 `wireinject` 构建标签后，因此调用点只有在生成后才会通过类型检查。Loom 图是普通包级变量，gopls、`go vet` 和 `go test` 都能看到它。代价是首次运行时调用点引用的初始化函数尚不存在；`loom generate` 会识别它即将修复的 `undefined: InitApp` 错误，同时继续报告其他所有类型错误。

## 快速开始

```go
package app

import "github.com/Xwudao/loom"

type Config struct{ DSN string }
type DB struct{ DSN string }
type App struct{ DB *DB }

func NewConfig() *Config    { return &Config{DSN: "memory://"} }
func NewDB(cfg *Config) *DB { return &DB{DSN: cfg.DSN} }
func NewApp(db *DB) *App    { return &App{DB: db} }

// AppGraph 是图声明；生成的函数为 InitApp。
var AppGraph = loom.Graph[*App](
    loom.Provide(NewConfig),
    loom.Provide(NewDB),
    loom.Provide(NewApp),
)
```

```bash
$ loom generate ./...
loom: wrote app/loom_gen.go ([InitApp])
```

```go
app, lifecycle, err := InitApp()
if err != nil {
    return err
}
if err := lifecycle.Start(ctx); err != nil {
    return err
}
defer lifecycle.Stop(shutdownCtx)
return app.Run(ctx)
```

在任意文件中添加 `//go:generate go run github.com/Xwudao/loom/cmd/loom generate`，即可将生成接入 `go generate ./...`。

## Provider

provider 是包级函数（或函数类型的包级变量），其签名必须是以下之一：

```go
func NewThing(...) T
func NewThing(...) (T, error)
func NewThing(...) (T, Cleanup)          // Cleanup = func(context.Context) error
func NewThing(...) (T, Cleanup, error)
```

`Cleanup` 也可以是 `func()`、`func() error` 或 `func(context.Context)`；Loom 会适配它。刻意不支持多值 provider（如 `func() (A, B)`），请将其拆成两个 provider。

注册 provider：

```go
loom.Provide(NewDB)
```

## 泛型

泛型构造函数必须实例化，类型参数会成为依赖键的一部分：

```go
func NewRepository[T any](db *DB) *Repository[T]

loom.Provide(NewRepository[User])     // 提供 *Repository[User]
loom.Provide(NewRepository[Article])  // 提供 *Repository[Article]
```

接受 `*Repository[User]` 的构造函数绝不会得到 `Article` 的实例。Loom 用 `go/types` 而不是字符串比较类型，因此别名、指针泛型和嵌套泛型的行为与编译器完全一致。

## 接口绑定

将构造函数结果显式绑定到接口：

```go
loom.As[UserStore](NewUserStore)
```

生成器会验证 `NewUserStore` 的结果是否实现 `UserStore`；若没有，会在调用处报告诊断：

```
loom: provider NewUserStore returns *httpserver.Store, which does not implement UserStore
at:
    internal/user/providers.go:22:2
```

具体类型仍然可用，因此 `As` 不会创建第二个实例。

图还可以暴露模块已提供的构造函数。绑定保留在图中；当接口所在包导入模块时这很重要——将 `As` 放在模块中会形成导入循环：

```go
var StoreModule = loom.Module(
    loom.Provide(NewStore),
)

// iface 导入 store，因此绑定不能放在 StoreModule 中。
var AppGraph = loom.Graph[*App](
    StoreModule,
    loom.As[iface.Finisher](store.NewStore),
    loom.Provide(NewApp),
)
```

在**同一**声明中列出同一构造函数两次仍会报错，因为那是冗余行，而不是对图导出内容的说明。

## 模块

将 provider 组成可复用的集合。模块可以嵌套；重复包含同一模块是无操作。

```go
var DatabaseModule = loom.Module(
    loom.Provide(NewDatabase),
    loom.Provide(NewRepository[User]),
    loom.Provide(NewRepository[Article]),
)

var ServiceModule = loom.Module(
    DatabaseModule,
    loom.As[UserStore](NewUserStore),
    loom.Provide(NewUserService),
)
```

## Supply

使用 `loom.Supply` 注入已有值。表达式会原样复制到生成代码中，因此必须可重定位（标识符、限定名、字面量、调用）：

```go
loom.Supply(config)
loom.Supply(Version{Major: 1, Minor: 2})
```

注意，Go 会在包初始化时计算一次参数，并在生成的初始化函数内再次计算。请先将有副作用的表达式赋给包级变量。

## 生命周期

`*loom.Lifecycle` 可以注入。为长生命周期服务注册启动/停止回调：

```go
func NewHTTPServer(lc *loom.Lifecycle, cfg *Config) *HTTPServer {
    server := &HTTPServer{Addr: cfg.Addr}
    lc.Append(loom.Hook{
        OnStart: func(ctx context.Context) error { return server.Listen(ctx) },
        OnStop:  func(ctx context.Context) error { return server.Close() },
    })
    return server
}
```

钩子按注册顺序在 `Start` 时运行，按逆序在 `Stop` 时运行。若某个钩子启动失败，已启动的钩子和清理函数都会回滚。

有两种方式可注入 `context.Context`。`loom.WithContext()` 会传递调用方的 context，并为生成函数添加前置 `ctx` 参数：

```go
var AppGraph = loom.Graph[*App](
    loom.WithContext(),
    ...
)
```

也可以像其他依赖一样由图提供它，这正是带有 `ProvideContext` 函数的 Wire injector 所做的。显式 provider 优先于 `WithContext`，因此 `loom.Provide(ProvideContext)` 会保持生成函数签名不变。

## 清理和回滚

构造函数可在返回值的同时返回清理函数。Loom 会将其注册到生命周期中，因此：

- 构造失败时，已构造的所有资源按逆序释放（`Lifecycle.Rollback`）；
- `Lifecycle.Stop` 时，先停止已启动的钩子，然后运行清理函数，二者都按注册逆序执行。

同一资源不要既返回清理函数又注册 `OnStop` 钩子。

## 生成的函数

每个图生成一个函数，名称由图变量名决定：

| 声明 | 生成的函数 |
| --- | --- |
| `var AppGraph = loom.Graph[*App](...)` | `InitApp` |
| `var workerGraph = loom.Graph[*Worker](...)` | `InitWorker` |
| `var AppGraph = loom.Graph[*App](loom.Name("BuildApp"), ...)` | `BuildApp` |

签名稳定：

```go
func InitApp() (*App, *loom.Lifecycle, error)
// 使用 loom.WithContext() 时：
func InitApp(ctx context.Context) (*App, *loom.Lifecycle, error)
```

生成的代码写入 `loom_gen.go`，经 gofmt 格式化，且仅在内容实际变化时重写。

### 引导和重新生成

Loom 没有 stub 文件，因此首次运行时初始化函数尚不存在，类型检查器会将每个调用点报告为 `undefined`。这是预期行为，不是错误：`loom generate` 会容忍它将创建的准确函数名（如 `undefined: InitApp`），所以可以在同一提交中编写图和调用点。其他错误仍会报告。

生成是全有或全无的：所有包均在写入任何文件前完成解析和渲染，因此一个包的诊断不会导致其他包只生成一半。若图有效但某个符号已过期且类型检查器无法发现，生成调用点的编译失败就是最后防线。

变量按其保存的类型命名（`Repository[User]` 变为 `userRepository`）。当该名称已被使用时，Loom 在以下情况下更倾向于显式包限定名而非数字后缀：

| Provider 返回值 | 名称 | 原因 |
| --- | --- | --- |
| `*user.Repository` | `userRepository` | 空闲 |
| `*data.Data` | `dataData` | `data` 是包自身的导入别名 |
| `*cmd.MainApp`，图名为 `mainApp` | `cmdMainApp` | `mainApp` 是函数自身 |
| 两次 `Repository[User]` | `userRepository2` | 已足够描述；数字后缀即可 |

缺失 provider、循环和重复项会报告完整路径：

```
loom: cannot build *App

dependency path:
    *App
      -> *UserService
      -> UserStore  (missing)

providers:
    internal/app/app.go:14:6       NewApp(*UserService)
    internal/user/service.go:13:6  NewUserService(UserStore)

hint:
    provider NewUserStore returns *userStore, which implements UserStore;
    bind it with loom.As[UserStore](NewUserStore)
```

## Loom 不是什么

Loom 绝不在运行时解析依赖。没有容器、`Resolve`、`Get` 或反射。唯一的运行时原语是 `loom.Lifecycle`，即一个有序的钩子和清理函数列表。

0.1 版本刻意未提供具名/键控依赖、可选依赖、值组、装饰器、作用域（瞬态/请求）和运行时替换。
